# November 9 hardening release

This release adds durable manual-order recovery, preserves the last active
administrator under concurrent changes, updates Python/npm dependencies and adds
real PostgreSQL, Redis and browser CI coverage. Earlier fixes in the release also
restrict metrics, TLS verification, replay writes and token/session handling.
The Today overview keeps long alert lists inside a scrolling panel. The global
kill switch now stops strategy processes as well as flattening positions.

## Compatibility

- The ticket uses POST `/api/ManualOrders/keyed`; an old API has no such route and cannot accidentally book a retry during rollout/rollback. The legacy POST alias also enforces keys in this release.
- Manual-order POST clients must send a non-empty UUID `clientOrderId`, stable
  across retries. A different payload with the same account/key returns 409.
  GET `/api/ManualOrders/receipts/{clientOrderId}` reads the caller's committed result.
- The fill, protection and receipt commit together. Replays return the original
  result even if quotes or instrument availability subsequently change. Same-key
  validation waits for an in-flight booking; a refusal cannot race a successful fill.
- The ticket keeps an unresolved order across a same-tab reload. Order buttons
  require the instrument endpoint's idempotency capability, so a new web bundle
  cannot silently submit to an old API during a rollout. Old browser tabs must refresh.
- Legacy account deletion refuses the last active administrator and accounts with
  trading history. Disable those accounts through People instead.
- Kill-switch activation serializes with strategy starts and releases. New runs
  are refused while it is active; releasing it never restarts stopped runs.
  An interrupted stop resumes on API startup, and an incomplete stop returns an
  error with the remaining runs/positions. Risk provides a retry without releasing
  the switch. A browser disconnect does not cancel an already persisted stop.
- The session migration invalidates pre-migration credentials. Users must sign in
  again; reverting application binaries must not resurrect those credentials.
- CPython 3.12 installs use complete hashes. News scoring needs the separately locked
  Linux CPU research profile; see [Python environments](python-dependencies.md).

## Release checks

1. Confirm the exact commit passed every CI job, including Timescale migrations,
   real Redis recovery, browser flows and the optional Linux research profile.
2. Record the active release SHA, process/run inventory, current Python package
   inventory and a database backup/restore location. Keep last-good API/web artifacts
   and the previous Python environment. Rehearse restore in a disposable database.
3. Build and test the replacement Python environment at its final path. Keep model
   caches outside it. Configure the new interpreter only at the quiet-desk window.
4. Honour the desk's live-run and market-hours gate. A manual book can remain open;
   active strategy runners require the normal close workflow. Do not use `deploy-now`
   merely to bypass an active run.
5. Generate local settings so the API and Prometheus share the new metrics token.
   Apply monitoring/container changes in the maintenance window and verify authenticated
   scraping and Redis health. Do not expose token values in logs or release notes.
6. Deploy the API and web from the validated commit. Check the deployed SHA, migration
   history, health, sign-in, protected metrics, UI pages, provider health and feed age.
   Verify live broker/profile reads without submitting orders. No production paper or
   real trades should be created merely for a smoke check.

## Rollback

Stop new order submissions and active runners before a rollback. Prefer a forward
fix or last-good **compatible** application build while leaving additive schema in
place. The receipt table must survive once orders have been accepted: dropping it
or restoring a pre-fill database snapshot would erase retry history and risk duplicate
orders. An older API that ignores client IDs is not a safe order-taking rollback;
keep the ticket disabled until a compatible API is restored. Preserve the session
revocation cutoff even when reverting auth changes.

Point the configured Python executable to the retained prior environment and restart
only the affected services during the quiet window. Restore API/web artifacts as a
pair. Recheck health, authentication, scraping and feed freshness. Record which SHA
and environment actually run; a successful Git push is not deployment evidence.
